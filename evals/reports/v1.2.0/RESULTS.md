# v1.2.0 RAG 评测记录

日期：2026-10-20（Asia/Shanghai）。固定集合：60 条，215 份资料。
本报告记录一次真实 BGE + DeepSeek 批量实验，不是人工标注的生产准确率，也没有统计显著性结论。
公开数据与项目合成边界样本分别保留切片，后者尚待独立人工复核。

正确性和完整性是 0/1/2 评分后的归一化平均值，不能把 0.8667 写成“86.67% 的答案完全正确”。
引用覆盖率的旧值为零，是因为旧版没有事实与行内编号的对应关系，不是说旧版完全没有召回来源。
token F1 下降，说明长答案、措辞和中英文表达会影响词面分数；本轮不能宣称所有指标都提高。

批量隔离运行器记录的平均单题耗时约 0.74 → 1.82 秒。
它包含该样本的内存库准备、查询和生成，不包含首次文档建索引、HTTP 或离线评分，
且使用四路并发和热缓存，不是线上首字延迟或 SLA。新版本 SSE 会等待核验完成再发送答案。

IDF 加权替代原有词面 Dice 分数参与混合排序，不更换向量模型、不训练模型。

| 切片 | 指标 | 原策略 | IDF |

| 开发（32 条有证据） | Recall@5 | 0.8125 | 0.8333 |
| 开发 | MRR | 0.8047 | 0.8370 |
| 保留（22 条有证据） | Recall@5 | 0.8636 | 0.9242 |
| 保留 | MRR | 0.8409 | 0.8750 |

先在开发切片比较，再核对保留切片，因此将 RAG_KEYWORD_IDF_ENABLED 默认设为 true。
但此前开发已经查看过全量问答输出，不能宣称这是一份完全盲测结果。
所有切片数据均为小规模、限定候选库评测，不等同于全量 Wikipedia 或实际客户知识库。

## 仍存在的限制与失败类型

- 引用原文支持一个陈述，不代表它回答了正确对象：本轮仍有同名地点混淆样本。
- 多跳问题可能漏召回支持链，已引用的局部事实也可能不构成完整答案。
- 在线语义核验可能误拒答或误判，部分答案与澄清边界仍需人工复核。
- 生成器和离线评分器均使用 deepseek-chat，请求模型名不是不可变模型快照，
  同模型评分存在偏好，温度和服务端变化也会影响结果。
- 历史是指定测试消息，不代表自由运行的完整多轮对话已经系统验收。
- 对资料过期、冲突、数字单位及中文领域知识的覆盖仍有限。
- 不应将本次小样本分数或一次运行的差值作为生产收益、零幻觉或人工准确率写入简历。

后续优先人工复核候选报告中的失败样本与一部分成功样本，记录人与评分器的分歧，
再扩大业务资料、真实用户问题和独立评分模型的覆盖。

## 工程验证

本地 88 项 pytest 通过，语句覆盖率 75%；ruff 与前端 JavaScript 语法检查通过。
覆盖率统计包含新增评测模块，不与旧版 92% 文档值作回答质量比较。
本地无 Docker 命令，因此没有宣称容器镜像已构建验证。

发布归档将数据外层 CRLF 规范为 LF，以使 Windows 与 GitHub 上的哈希一致。
样本 JSON 值和模型输出未改变；原始运行 metadata 与规范化前哈希另行保留，见 dataset-normalization.json。
